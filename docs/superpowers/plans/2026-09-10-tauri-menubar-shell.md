# Tauri Menu-Bar Mac Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a always-running macOS menu-bar app that hosts the existing auto_trader UI in a WKWebView so the browser-driven live engine cannot be killed by a stray ⌘W or a closed browser.

**Architecture:** A new `tauri-shell/` Tauri v2 project, sibling to `frontend/` and `backend/`, loads a user-settable URL (default `http://localhost:5173`). The shell owns the tray icon, the global hotkey, close-to-hide, autostart, the settings store, the connection splash, the dock badge and the App Nap assertion. The web app stays a plain web app: two guarded seams in `frontend/src/lib/` (native notifications, live-engine status glyph) call into the shell only when it is present.

**Tech Stack:** Tauri v2 (Rust 1.95, WKWebView), plugins `global-shortcut`, `autostart`, `window-state`, `store`, `notification`; `objc2` for the App Nap assertion; React 19 + Vite + vitest on the frontend side.

**Spec:** `docs/superpowers/specs/2026-07-08-tauri-menubar-wrapper-design.md`

## Global Constraints

- **macOS only, personal single-machine tool.** No code signing, no notarization, no auto-update, no distribution.
- **The shell never starts the backend or Vite.** It loads a URL and nothing else. `backend/` does not change in this plan.
- **Default UI URL:** `http://localhost:5173`. Backend at `http://localhost:8000` is reached by the page, not the shell.
- **Global hotkey:** `⌘⌥T`, defined as one constant in `src-tauri/src/main.rs`.
- **Only the tray Quit item truly quits.** Red button, `⌘W` and `⌘Q` all hide.
- **Launch at login defaults to on.**
- **Frontend seams must be guarded** so a plain-browser run behaves exactly as today. Every frontend change ships with a vitest test proving the non-Tauri path is unchanged.
- **Copy rule (repo-wide):** no em dashes and no double hyphens in any prose or UI text, including `settings.html`, `splash.html` and this plan's commit messages.
- **Git rules (repo-wide):** this worktree is shared with parallel sessions. Stage by explicit path, never `git add -A`, never stash, clean or restore. Commit to `main`; do not create a branch.
- **Test scope rule (repo-wide):** run only the affected frontend test files, never the whole suite.

### Task 2: Prove the IPC bridge from the Vite origin

The page is served from `http://localhost:5173`, which is a remote origin as far as Tauri v2 is concerned, not the bundled `tauri://localhost`. Capabilities are scoped by window and origin, so command access has to be granted explicitly. Both frontend seams (Tasks 8 and 9) depend on this working, so it is proven with a trivial command before any real bridge code is written.

**Files:**
- Create: `tauri-shell/src-tauri/capabilities/default.json`
- Modify: `tauri-shell/src-tauri/build.rs`
- Modify: `tauri-shell/src-tauri/src/main.rs`
- Create: `frontend/src/lib/shellBridge.ts`
- Create: `frontend/src/lib/shellBridge.test.ts`

**Interfaces:**
- Consumes: the scaffolded app from Task 1.
- Produces:
  - Rust: `#[tauri::command] fn ping() -> String`
  - TypeScript in `frontend/src/lib/shellBridge.ts`:
    - `export function inShell(): boolean`
    - `export async function shellInvoke(cmd: string, args?: Record<string, unknown>): Promise<unknown>`

- [ ] **Step 1: Add the capability file granting the Vite origin IPC access**

`tauri-shell/src-tauri/capabilities/default.json`:

```json
{
  "$schema": "../gen/schemas/macOS-schema.json",
  "identifier": "default",
  "description": "Shell commands reachable from the locally served UI.",
  "windows": ["main"],
  "remote": {
    "urls": ["http://localhost:*", "http://127.0.0.1:*"]
  },
  "permissions": ["core:default", "allow-ping"]
}
```

A second capability file, `capabilities/served-ui.json`, carries the `remote` block and grants the same commands to the served UI; `default.json` (no `remote` block) covers the shell's own bundled pages and lists `"main"` and `"settings"` in `windows`. Keep them split: a capability's `windows` list gates the settings and splash pages too, and a settings window missing from it silently loads with empty fields.

Note for the implementer, and this bites EVERY later task that adds a command: two things gate an invoke from the served UI.

1. `remote.urls` is what makes any command callable from a page the shell did not bundle. Without it the call fails with "not allowed on origin".
2. App-level commands (ours, as opposed to a plugin's) have no ACL entry unless `build.rs` declares them, and the capability cannot grant what does not exist. A command missing from that list fails with "ping not allowed. Plugin not found", which reads like a plugin problem and is not one.

So every new command added from here on needs THREE edits, not one: `generate_handler!`, the `commands(&[...])` list in `build.rs`, and an `allow-<command>` entry in this capability. Plugin permissions (notification, autostart, store, window-state, global-shortcut) go in the same `permissions` array as `<plugin>:default`.

- [ ] **Step 6: Write the bridge**

`frontend/src/lib/shellBridge.ts`:

```ts
// The one seam between the web app and the native Tauri shell (tauri-shell/).
// Everything here is a no-op in a plain browser: `inShell()` is false and
// `shellInvoke` resolves to null, so callers never need a guard of their own.

type TauriGlobal = { core?: { invoke?: (cmd: string, args?: Record<string, unknown>) => Promise<unknown> } };

function tauri(): TauriGlobal | null {
  const g = (window as unknown as Record<string, unknown>).__TAURI__;
  return g ? (g as TauriGlobal) : null;
}

/** True only when the page is running inside the native shell. */
export function inShell(): boolean {
  return tauri() !== null;
}

/** Call a shell command. Resolves to null in a browser, or if the call fails:
 *  the shell is a convenience layer, so a broken bridge must never break the
 *  trading UI. */
export async function shellInvoke(
  cmd: string,
  args?: Record<string, unknown>,
): Promise<unknown> {
  const invoke = tauri()?.core?.invoke;
  if (!invoke) return null;
  try {
    return await invoke(cmd, args);
  } catch {
    return null;
  }
}
```

- [ ] **Step 2: Intercept the close request and own the menu**

In `main.rs`:

```rust
use tauri::menu::{AboutMetadata, MenuBuilder, SubmenuBuilder};
use tauri::{Manager, WindowEvent};

fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_window_state::Builder::default().build())
        .invoke_handler(tauri::generate_handler![ping])
        .setup(|app| {
            // The default macOS app menu binds Cmd+Q to a real quit. Rebuild the
            // app submenu without it: hiding is the only keystroke-reachable
            // exit, so nothing reflexive can kill the live engine. Cmd+W is
            // handled by the close-request interceptor below.
            let app_menu = SubmenuBuilder::new(app, "Auto Trader")
                .about(Some(AboutMetadata::default()))
                .separator()
                .hide()
                .hide_others()
                .separator()
                .close_window()
                .build()?;
            let edit_menu = SubmenuBuilder::new(app, "Edit")
                .undo()
                .redo()
                .separator()
                .cut()
                .copy()
                .paste()
                .select_all()
                .build()?;
            let menu = MenuBuilder::new(app).items(&[&app_menu, &edit_menu]).build()?;
            app.set_menu(menu)?;
            Ok(())
        })
        .on_window_event(|window, event| {
            if let WindowEvent::CloseRequested { api, .. } = event {
                // Hide instead of closing: the WKWebView keeps running, so the
                // browser-driven live engine stays armed.
                api.prevent_close();
                let _ = window.hide();
            }
        })
        .run(tauri::generate_context!())
        .expect("error while running auto-trader shell");
}
```

- [ ] **Step 2: Build the tray in setup**

In `main.rs`, inside `.setup(...)` after the menu code:

```rust
use tauri::image::Image;
use tauri::menu::{MenuBuilder as TrayMenuBuilder, MenuItemBuilder};
use tauri::tray::{MouseButton, MouseButtonState, TrayIconBuilder, TrayIconEvent};

fn show_window(app: &tauri::AppHandle) {
    if let Some(w) = app.get_webview_window("main") {
        let _ = w.show();
        let _ = w.unminimize();
        let _ = w.set_focus();
    }
}

fn toggle_window(app: &tauri::AppHandle) {
    let Some(w) = app.get_webview_window("main") else { return };
    let visible = w.is_visible().unwrap_or(false);
    let focused = w.is_focused().unwrap_or(false);
    if visible && focused {
        let _ = w.hide();
    } else {
        show_window(app);
    }
}
```

and, in `setup`:

```rust
let show = MenuItemBuilder::with_id("show", "Show Window").build(app)?;
let hide = MenuItemBuilder::with_id("hide", "Hide Window").build(app)?;
let reload = MenuItemBuilder::with_id("reload", "Reload").build(app)?;
let settings = MenuItemBuilder::with_id("settings", "Settings...").build(app)?;
let quit = MenuItemBuilder::with_id("quit", "Quit").build(app)?;
let tray_menu = TrayMenuBuilder::new(app)
    .items(&[&show, &hide, &reload, &settings, &quit])
    .build()?;

TrayIconBuilder::with_id("main-tray")
    .icon(Image::from_bytes(include_bytes!("../icons/tray-idle.png"))?)
    .icon_as_template(false)
    .menu(&tray_menu)
    .show_menu_on_left_click(false)
    .on_menu_event(|app, event| match event.id().as_ref() {
        "show" => show_window(app),
        "hide" => {
            if let Some(w) = app.get_webview_window("main") {
                let _ = w.hide();
            }
        }
        "reload" => {
            if let Some(w) = app.get_webview_window("main") {
                let _ = w.eval("window.location.reload()");
            }
        }
        // Wired in Task 6.
        "settings" => {}
        "quit" => app.exit(0),
        _ => {}
    })
    .on_tray_icon_event(|tray, event| {
        if let TrayIconEvent::Click { button: MouseButton::Left, button_state: MouseButtonState::Up, .. } = event {
            toggle_window(tray.app_handle());
        }
    })
    .build(app)?;
```

use serde::{Deserialize, Serialize};
use tauri::{AppHandle, Wry};
use tauri_plugin_store::StoreExt;

pub const DEFAULT_URL: &str = "http://localhost:5173";
const STORE_FILE: &str = "settings.json";

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Settings {
    pub url: String,
    pub autostart: bool,
}

impl Default for Settings {
    fn default() -> Self {
        // Autostart defaults on: after a reboot the shell comes back on its own
        // and the menu-bar icon is there without a manual step.
        Self { url: DEFAULT_URL.to_string(), autostart: true }
    }
}

impl Settings {
    pub fn from_json(v: &serde_json::Value) -> Self {
        let d = Settings::default();
        Settings {
            url: v.get("url").and_then(|x| x.as_str()).unwrap_or(&d.url).to_string(),
            autostart: v.get("autostart").and_then(|x| x.as_bool()).unwrap_or(d.autostart),
        }
    }

    pub fn validate_url(raw: &str) -> Result<String, String> {
        let parsed = url::Url::parse(raw).map_err(|e| e.to_string())?;
        match parsed.scheme() {
            "http" | "https" => Ok(parsed.to_string()),
            other => Err(format!("unsupported scheme: {other}")),
        }
    }
}

pub fn load(app: &AppHandle<Wry>) -> Settings {
    let Ok(store) = app.store(STORE_FILE) else { return Settings::default() };
    let mut obj = serde_json::Map::new();
    if let Some(v) = store.get("url") {
        obj.insert("url".into(), v);
    }
    if let Some(v) = store.get("autostart") {
        obj.insert("autostart".into(), v);
    }
    Settings::from_json(&serde_json::Value::Object(obj))
}

pub fn save(app: &AppHandle<Wry>, s: &Settings) -> Result<(), String> {
    let store = app.store(STORE_FILE).map_err(|e| e.to_string())?;
    store.set("url", serde_json::json!(s.url));
    store.set("autostart", serde_json::json!(s.autostart));
    store.save().map_err(|e| e.to_string())
}
```

// Mirror the live engine's status onto the native shell's menu-bar glyph.
// A no-op in a plain browser, and the only place that knows the mapping from
// LiveStatus to the shell's three-colour tray icon.
import { liveStateSignal } from "./liveController";
import type { LiveStatus } from "./liveState";
import { inShell, shellInvoke } from "./shellBridge";

type ShellStatus = "live" | "idle" | "error";

function glyphFor(status: LiveStatus): ShellStatus {
  switch (status) {
    case "armed":
      return "live";
    case "lost-lease":
      return "error";
    default:
      return "idle";
  }
}

/** Start mirroring; returns an unsubscribe. Safe to call in any environment. */
export function startShellStatusMirror(): () => void {
  if (!inShell()) return () => {};
  let last: ShellStatus | null = null;
  return liveStateSignal.subscribe((s) => {
    const next = glyphFor(s.status);
    if (next === last) return;
    last = next;
    void shellInvoke("set_status", { state: next });
  });
}
```

`Signal.subscribe` (`frontend/src/lib/signals.ts:25`) does NOT emit the current value on subscribe, and it returns an unsubscribe closure. The call counts in the test above are pinned to that behaviour; the mirror therefore reports nothing until the first real transition, which is correct because the tray starts on the idle glyph.

}

### Task 11: Prevent App Nap and background throttling

This is the only task with real Cocoa FFI, and it is the one correctness-critical piece of the shell: a hidden window whose timers get coalesced is a live engine that misses bars. It is sequenced last because it is the most likely to need iteration.

- [ ] **Step 3: Hold the activity assertion**

`tauri-shell/src-tauri/src/appnap.rs`:

```rust
// macOS App Nap and timer coalescing throttle hidden apps. The live engine runs
// inside the web view WHILE the window is hidden, so a throttled timer or a
// stalled WebSocket is a missed bar. Hold a process-lifetime activity assertion
// and leak it deliberately: releasing it is exactly what we never want.
#[cfg(target_os = "macos")]
pub fn hold_activity_assertion() {
    use objc2_foundation::{NSActivityOptions, NSProcessInfo, NSString};

    let info = NSProcessInfo::processInfo();
    let reason = NSString::from_str("auto_trader live engine runs while hidden");
    let options = NSActivityOptions::UserInitiated
        | NSActivityOptions::IdleSystemSleepDisabled
        | NSActivityOptions::LatencyCritical;
    let token = unsafe { info.beginActivityWithOptions_reason(options, &reason) };
    // Never ends: the assertion must outlive every window state.
    std::mem::forget(token);
}

#[cfg(not(target_os = "macos"))]
pub fn hold_activity_assertion() {}
```

Note for the implementer: on objc2-foundation 0.3 the option variants have no `NSActivity` prefix (`NSActivityOptions::UserInitiated`), and neither call needs an `unsafe` block. The exact method and option names shift between versions. If `beginActivityWithOptions_reason` does not resolve, check the crate's docs for the current spelling (`beginActivityWithOptions:reason:`) and adjust; the semantics required are user-initiated plus idle-system-sleep-disabled, and latency-critical is a bonus, not a requirement. Drop `NSActivityLatencyCritical` first if it causes trouble.

Add `mod appnap;` to `main.rs` and call `appnap::hold_activity_assertion();` at the top of `setup`.
