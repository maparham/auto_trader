# TRENDLINES nearest first selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stage 3 walks the gate-passing lines nearest to the close first, ties by `rankLines`, so drawn lines and `tl_1 .. tl_N` favour lines near price.

**Architecture:** One ordering helper per port (`nearestFirst` in TS, `nearest_first` in Python) replaces the `rankLines` / `rank_key` sort in front of `selectLevels` / `select_levels`. Everything downstream (merge, per pivot, Max Trendlines cut, early stop, pins) is unchanged code that now sees the new order. The live cap keeps `compareSurvival`.

**Tech Stack:** TypeScript + vitest, Python + pytest, TS-written golden read by Python.

**Spec:** `docs/superpowers/specs/2026-09-24-trendlines-nearest-first-selection-design.md`

- [ ] **Step 3: Implement in `trendlines.ts`** (place `nearestFirst` directly above `selectDrawnLines`):

```ts
/** STAGE 3 WALK ORDER: nearest to the close first, at `atIdx`. Ties (exact
 * float equality of the distance) go to rankLines, so strength decides only
 * between lines equally far from price. Quality is the filters' job, not the
 * order's. Distances are computed once per line, not in the comparator.
 * Mirrored by nearest_first in trendlines.py (same float operations, same
 * tie-break, both sorts stable over the same input order). */
export function nearestFirst(
  lines: readonly TrendLine[],
  atIdx: number,
  close: number,
): TrendLine[] {
  const dist = new Map<TrendLine, number>();
  for (const l of lines) dist.set(l, Math.abs(projectAt(l, atIdx) - close));
  return lines.slice().sort((a, b) => dist.get(a)! - dist.get(b)! || rankLines(a, b));
}
```

def nearest_first(lines: list[TrendLine], at_idx: int, close: float) -> list[TrendLine]:
